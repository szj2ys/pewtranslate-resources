How blocks and exact text work

A separator starts with two line feeds (LF), optionally with only ASCII spaces or tabs between them, and includes any further such blank lines. Every nonempty piece between separators is a block, including its leading/trailing spaces and single line breaks. Leading/trailing separators remain recorded. This is a layout rule, not linguistic paragraph detection.

Preview the split before freezing. Positions are zero-based UTF-16 ranges [start, end), with the end excluded. Repeated equal blocks get different IDs. Browsers normalize textarea CRLF/CR line endings to LF: we retain the accepted editor value, not original file bytes. Empty or all-whitespace sides are rejected.

Plain text is isolated from labels. Unpaired UTF-16 surrogates and certain controls are shown as visible \uXXXX escapes in previews/reports; exact escaped representations and the JSON retain the accepted units. No text is repaired.

Texts are fixed for this revision. Export first if you want to keep this work. Starting a new revision clears its associations and notes; none are carried to the new text.

2Associate blocks manually

Choose one or more available blocks on each side, then create a group. Document order stays fixed even when associations cross. Unlink a group before reassigning its blocks. Block notes remain with their exact block when a group is removed.

Unassigned is an administrative state, not an omission or translation error. No association count measures correctness. Each block and group can have a note of at most 1,000 UTF-16 units.
