Turn the observations into a review

  1. Check rejected inputs. Underscores, multiple tags on one line and an identifier outside this API’s accepted syntax need a source check. A rejection is not a full BCP 47 verdict.
  2. Keep the intended distinctions. Two rows can canonicalize to the same identifier. Review that mapping before merging anything; this tool does not deduplicate your list.
  3. Test the actual user interface. A date-formatting lookup can use a broader locale. Inspect real formatting, language labels, fonts and content in each supported runtime.

If these tags will appear in a language selector, ask people what wording they recognize and prefer. PewTranslate’s guide to welcoming multilingual visitors discusses offering choices without guessing someone’s language. A browser tag cannot establish a person’s preference or available translation assistance.

What each result means—and what it does not

Canonicalization: Intl.getCanonicalLocales([tag]) runs separately on each trimmed row. Accepted means this runtime accepted its structure and returned a canonical identifier. It does not query a registry. Some BCP 47 forms are outside the API’s accepted Unicode locale-identifier syntax.

DateTimeFormat lookup: supportedLocalesOf([canonical], {localeMatcher: "lookup"}) asks whether this one service can match without its runtime default locale. “No non-default match” is not an invalid or nonexistent language. A successful lookup may resolve to a parent locale or ignore extensions. The separately constructed formatter’s resolvedOptions().locale is shown; equality is not proof of complete dialect or extension behavior.

Localized names: Intl.Locale(canonical).baseName supplies the language/script/region/variant identifier, without extensions or private-use subtags, to Intl.DisplayNames.of. Names use type: "language", languageDisplay: "standard", localeMatcher: "lookup" and fallback: "none". No returned name means no localized name was returned for that query—not that the language does not exist. The requested and actual resolved display locales are both shown.

Partial failures: missing APIs, rejected identifiers, API exceptions and missing names are separate states. A display-locale setting error does not erase canonicalization or date-formatting results. Browser versions, builds and locale data can produce different results.

Bounds and output: input above 64 KiB or 1,000 rows is rejected in full. Individual trimmed rows above 256 UTF-16 code units are kept but not passed to the APIs. The display-locale setting is limited to 128 code units. Results appear 100 rows at a time; CSV includes the whole inspected batch. Line endings are row separators, not part of each exported original field.

CSV safety: every field is quoted, internal quotes are doubled, and formula-like cells receive a leading apostrophe. That protective prefix intentionally changes the exported field, not the source text. Keep it when opening untrusted values in a spreadsheet.

API references: ECMA-402, canonicalization, DateTimeFormat matching and DisplayNames options.
