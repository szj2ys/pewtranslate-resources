Literal Transcript Alignment Reviewer

Compare a reference transcript and an ASR draft for the same short segment. Find literal token differences, return to their exact source positions, and download a review handoff.

Check the reference against the actual recording first. An outline, translation, or paraphrase is not a matching reference. This page processes text only: it cannot verify either transcript, recognize speech, or judge meaning, translation quality, intelligibility or service readiness.

2. Review the literal alignment

Substitution means two unlike tokens were paired; deletion means a reference token has no draft token; insertion means a draft token has no reference token. These describe this alignment, not verified mistakes. A small difference can change meaning; a large difference can reflect formatting or a faulty reference.

Each position is a zero-based UTF-16 range [start, end) in its current editor. A gap is not a token. Previews use quoted ASCII escapes for non-ASCII and control code units so hidden or directional characters cannot alter the labels. Use Select to inspect the original token.

    Understand the comparison

    Tokenization and original text

    Consecutive separators create no empty tokens. Separator-only differences do not change the alignment or rate. Non-breaking spaces, zero-width spaces, hyphens, apostrophes, numbers and punctuation are not expanded, removed or normalized. Text without the listed separators becomes one token; this is not a segmenter for unspaced languages.

    The tool never rewrites either editor. Browsers can normalize pasted CRLF or CR line endings to LF. Positions and the exported text refer to the current editor values, not original file bytes or pre-paste text. Supplementary characters occupy two UTF-16 units; offsets are not grapheme or visible-letter counts. JSON escapes preserve even isolated surrogate units.

    Costs, direction, ties and the rate

    The alignment transforms reference tokens into draft tokens. An exact token match costs 0; substitution, deletion and insertion each cost 1. Dynamic programming minimizes the total cost over the complete accepted excerpt. It does not use time, speakers, semantic similarity or word importance.

    Backtracking starts at the end. When costs tie, prefer a diagonal pair (match or substitution), then deletion, then insertion. A tie notice means this chosen path encountered an alternative optimal predecessor. Other equally minimal alignments can assign different operations and positions; this deterministic path is not uniquely correct.

    Let N be reference tokens, H draft tokens, C exact matches, S substitutions, D deletions and I insertions. N = C + S + D; H = C + S + I; distance = S + D + I. The displayed literal token difference rate is 100 × distance ÷ N, rounded to two decimal places. It can exceed 100%. With N = 0 it is undefined, including when both sides are empty; counts remain available.

    This uses the familiar word-error-rate formula under this page's own literal tokenization and unit costs. It is not an accuracy percentage, model benchmark or NIST/SCLITE reproduction. SCLITE's documented default alignment weights are 0/3/3/4 for match/insertion/deletion/substitution, with additional scoring options. Comparing rates across different inputs or rules can mislead.

    Bounds, lifecycle and local processing

    Unit and token limits are checked before allocating the matrix; its complete cell count is checked before computation. No truncated excerpt is reported as complete. Editing either side, clearing or loading an example invalidates previous results and export. Work yields between groups of rows; an obsolete run cannot publish a result after an edit.

    The page contains its own code and styles. No audio, network requests, analytics, cookies, persistent storage or external packages are used. Text stays in page memory until you clear, close or refresh it. A user-triggered JSON download saves supplied text on your device. Reference links navigate externally only when activated.

    Continue the human review

    Return to the recording and resolve questionable wording with the speaker or reviewer. The PewTranslate guide to checking sermon transcript and translation errors separates audio, source transcript, context and translation review. This utility cannot decide which stage caused a difference.
