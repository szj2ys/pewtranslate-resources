Placeholder Review Guide

Preserve named placeholders when localizing interface text

Start with a small contract

A localized interface string may carry values supplied later by the application: a person's name, a room, or a date. Changing a placeholder can hide a value or break rendering. This tutorial teaches one narrow review step: compare named placeholder occurrences before testing the final wording in its application.

Every example below is synthetic English. The candidate strings are deliberate rephrases, not translations or reports of production use. Even the first matching example changes the message's meaning. That is intentional: equal token counts cannot establish that a sentence says the right thing.

First ask the application owner which fields are required, which can repeat, and what values they receive. Keep that contract beside both original strings. A source string is evidence to inspect, not an infallible specification.

Define the supported grammar

This checker accepts only named fields such as {person} and {room}. Names use ASCII letters or underscores first, followed by ASCII letters, digits, or underscores. They are case-sensitive. Double braces {{ and }} represent literal braces; {{person}} is literal text, not a field. Ordinary text may otherwise contain Unicode characters.

Positional fields, attribute or index access, conversions, every explicit format specification (including an empty colon), nested fields, and ICU plural syntax are rejected. Percent and dollar template syntaxes are outside scope. To avoid guessing, this small checker rejects every % and $ character, including literal percentages and currency symbols. Such rejection does not mean the original text is invalid. Route it to a checker for the application's actual format.

Python's parser identifies fields and malformed braces. A separate raw-syntax check enforces this narrower subset. Counting occurrences also catches a lost duplicate that a comparison of unique names would miss.

Copy and run the complete example

Save the following code as checker.py using a plain-text editor. Run python checker.py in that folder; use python3 if that is your Python command. It uses only the standard library and Python 3.10-compatible syntax. Prefer a currently supported Python release. No packages, account, or network connection are needed.

The comparison functions parse and count; they do not evaluate expressions, render incoming strings, or write files. The final demonstration renders only a fixed example with known string values. """Review a deliberately small named-brace subset; never rewrite text."""

from collections import Counter
from string import Formatter
import re


SUBSET = re.compile(
    r"(?:[^{}%$]|\{\{|\}\}|\{[A-Za-z_][A-Za-z0-9_]*\})*"
)


def counts(text: str) -> Counter:
    try:
        parts = list(Formatter().parse(text))
    except ValueError:
        raise ValueError("malformed brace syntax") from None
    # Check raw syntax too: parse() does not distinguish {name:} from {name}.
    if SUBSET.fullmatch(text) is None:
        raise ValueError("outside named-brace subset")
    return Counter(name for _, name, _, _ in parts if name is not None)


def compare(source: str, candidate: str) -> str:
    before, after = counts(source), counts(candidate)
    missing = dict(sorted((before - after).items()))
    added = dict(sorted((after - before).items()))
    if missing or added:
        return f"REVIEW missing={missing}; added={added}"
    return "MATCH counts only"


# Synthetic English strings: these are rephrases, not translations.
CASES = (
    ("reordered", "Hello {person}, open {room}.",
     "{room} is ready, {person}."),
    ("lost", "Open {room}, {person}.", "Open {room}."),
    ("renamed", "Hello {person}.", "Hello {name}."),
    ("repeated", "{person}, please ask {person}.",
     "{person}, please ask."),
    ("escaped", "Type {{person}} for {person}.",
     "For {person}, type {{person}}."),
    ("unsupported", "Hello {person}.", "Hello {person!r}."),
    ("malformed", "Hello {person}.", "Hello {person."),
)


if __name__ == "__main__":
    for label, source, candidate in CASES:
        try:
            result = compare(source, candidate)
        except ValueError as error:
            result = f"REJECT {error}"
        print(f"{label}: {result}")

    # Only render our fixed example with known, ordinary string values.
    print("rendered:", CASES[0][2].format_map(
        {"person": "Alex", "room": "Cedar"}
    ))

Read the actual output

The output below was produced by the complete script on Python 3.10.2. Missing means fewer occurrences than the source; added means more. Renaming therefore appears as one missing name and one added name. Reordering passes. The repeated example loses one occurrence. Escaped literal braces do not add a field. Unsupported and malformed input are rejected before comparison.

Review in the consuming application

A REVIEW result is a candidate for investigation, not an instruction to restore a token. Repetition may legitimately change with the wording. Check the application's contract, then render approved examples with known arguments through its real formatting path. Verify expected values, visible text, escaping, line wrapping, and accessibility in context.

MATCH means only equal occurrence counts within this subset. It cannot prove meaning, grammar, pluralization, correct order, runtime safety, or the application's escaping behavior. The demonstration does not authorize formatting arbitrary untrusted objects or evaluating strings as code.
