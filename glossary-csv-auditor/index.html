CSV dialect, bounds and failure behavior

This is a documented comma-separated dialect informed by RFC 4180, not a full standards certification. It accepts Unicode text, LF record breaks after browser CRLF/CR normalization, optional headers, quoted commas and line breaks, and doubled quotes inside quoted fields. A quote must start a field; after a closing quote only comma, record break or end is accepted. Spaces around an unquoted value are preserved; a space before an opening quote or after a closing quote is not silently removed.

A trailing comma creates a final empty field. A terminal record break does not create another record. An interior blank line is a one-empty-field record, not skipped. All records must have the first record's field count. Malformed quoting stops parsing without a partial glossary audit. Ragged records produce structural findings and block column auditing until corrected. Header-only and empty inputs are explicit states. A pasted BOM is ordinary field content, not automatically stripped.

Limits: 64,000 UTF-16 input units, 500 CSV records including a header, 50 columns, 20,000 total cells and 1,000 physical lines. Exceeding a limit produces no partial audit. Unpaired UTF-16 surrogate units are rejected because raw UTF-8 CSV export would not preserve them. At most 100 findings are added per display step; the download includes every finding.

Repeated-pair findings mark later occurrences and reference the first identical pair. Different-target findings mark every record whose exact source appears with more than one exact target, referencing one contrasting record rather than enumerating every pair. Empty and nonempty strings, spaces, case and Unicode composition remain distinct. No language inference, case folding, trimming or normalization occurs.

Export and privacy

CSV includes finding type, record and line references, selected column positions, selected strings, one related record where relevant, the original record text and a review note. Original record text retains quote syntax and embedded line breaks, excluding its terminating record break. Values use quoted fields, doubled quotes, CRLF output rows and a UTF-8 BOM.

Formula-like cells receive a leading apostrophe; the final column names fields receiving this protective prefix. The source editor is unchanged. Keep the prefixes when opening untrusted content in a spreadsheet; import behavior varies. Markup is inserted as literal DOM text. No external assets, storage or network calls are used; refreshing clears the working data. Reference links leave the tool only when followed.
